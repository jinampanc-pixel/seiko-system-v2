# Order cache and mobile save stabilization — 6 October 2026

Production Order Center navigation threw a `QuotaExceededError` while persisting `generated-order-artifacts-v1`. Its React initializer generated and rewrote garment/package identities for every cached order. Opening the list now only reads orders. Generation remains on a confirmed save, preserves existing package status, and treats a rejected derived-cache write as a cache failure rather than a failed shared save.

Order command acknowledgements and synchronization share a business-scoped order cache. When browser storage rejects a write, the acknowledged orders remain available in memory for the current page session. Order Center explains that an offline copy is unavailable. No draft, conflict or other business storage is evicted. Home uses the same read path. This is not durable offline storage: after closing or reloading, a working connection is required to fetch the latest D1 records.

An open workspace can be older than the version map advanced by polling. Existing-order saves now fetch the server revision and compare its `updatedAt` with the workspace base before sending the revision using its atomic expected version. A mismatch retains the draft and reports a conflict instead of overwriting newer records. New setup creation retains its existing creation flow. This does not retroactively protect an already-loaded older client; reload old app windows after deployment.

Save is a visible, disabled-while-pending button instead of an action hidden by a DOM enhancement. The existing mobile order menu is positioned within the viewport, with scrolling for short screens and 44px actions. No new enhancement layer or stylesheet is introduced.

Validation: full `npm test` passes (281 contract/runtime tests, production build and 3 render tests). Real browser workflows pass against the actual Orders API and isolated SQLite: stale workspace versus another-device save; rejected order and artifact cache writes; server-persisted Save & Close and reopening; draft retention; visible Save and complete menu bounds at 390×844 and 360×640. Existing creation, payment, document, archive/delete, status and fresh-browser scenarios also pass. Changed-file lint has no errors and three existing warnings. The failure-response test now routes list reads through the real test API while failing only the intended upsert.

Recovery of a specific affected order is an owner-authorized operational action, separate from this code change. Audit snapshots permit record-only recovery with revision, empty-record and field/product/measurement compatibility guards. The existing database update trigger records the resulting snapshot atomically. No business records, credentials or recovery SQL are committed here.
