# SEIKO UI review — 25 October 2026

## Problems found and fixes

| Problem | Fix |
| --- | --- |
| Pricing appeared before client/product setup. | Agreed pricing now follows the product section. |
| All product settings competed for space. | Compact product summaries; one product card opens at a time, including newly added products. |
| Cross symbols made deletion unclear; group-rule controls could overlap. | Trash icons with descriptive accessible names and dedicated layout columns. |
| Product measurement fields did not align consistently. | A shared product/quantity/measurement grid aligns matching headings without mixing their stored IDs. |
| A new person showed an incomplete TS/TP kit before group details were entered. | Entry explains which grouping detail is needed and resolves the complete kit from setup before saving. |
| Repeated manual entry required unnecessary clicking. | Name receives focus; Enter advances; Ctrl/Command+Enter saves and continues; Save & next handles both fresh people and existing lists. |
| A Speak button beside every field made dictation cumbersome. | One focused-field microphone beside the save controls; Alt+M / Option+M shortcut; touch control on mobile. |
| The operational module name was long and mixed setup with records. | Renamed Order management; agreed prices are edited in setup and reviewed alongside operational records in the workspace. |
| Header search occupied excess space and sat awkwardly. | An accessible magnifier icon beside the menu. |
| Legacy inline theme settings overrode SEIKO colours. | Navy, gold and cream now apply at the SEIKO app roots. |
| Back controls varied in size and appearance. | Shared styling, focus treatment and 44px touch targets across native and enhanced controls. |
| A separate history handler intercepted contextual Back controls. | Contextual controls retain their native return handlers and save guards. |
| Scan, Trace and secondary module pages lacked a direct Home return. | Consistent Back to Home control. |
| Scan overflowed the 360px viewport. | Shrinkable grid/input tracks and contained input widths. |
| Scan action text matched its dark background. | Contrasting cream labels on navy buttons; camera overlay text remains white. |
| Scan retained excessive empty panel height on phones. | Reduced mobile minimum heights. |

## Validation coverage

The responsive audit covers 16 views at 360, 390, 430, 768, 1024 and 1366px: Home, Orders, order setup, Labels, Scan, Trace, Production, Billing, Appearance settings, Access settings, Billing settings, billing asset editor, global search, invoice preview, quotation preview and delivery-challan preview. It checks page/control overflow, equal foreground/background colours on text buttons, visible Back target sizes, preview content and fit-screen zoom.

The workflow smoke suite also checks person/measurement entry, Google Sheets saves and conflicts, order management, receipt amendments, billing assets, document PDF generation, production sheets, labels, access editing, cache recovery and backups. All person fields remain editable in the connected sheet.

These are automated Chromium layout/workflow checks and a live desktop browser check. They do not establish real microphone recognition quality or physical iPhone, Android and Mac/Safari behaviour; browser dictation fallback remains available.
