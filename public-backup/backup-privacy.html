Backup privacy information

This page describes the independent Jinam backup runner and its Google Drive authorization.

Data used

The runner exports saved operational records, including orders, customers, production, billing, payments, settings and histories. Application accounts, passwords, sessions, passkeys and connector secrets are excluded from the business archive. Unsaved browser changes are not a complete database backup.

Storage and encryption

Business archives are encrypted with AES-256-GCM before upload. The configured owner-controlled computers and private Google Drive folder receive encrypted archives. Verification manifests contain snapshot dates, counts, checksums and file identities, not customer record bodies. File names, sizes and this verification metadata are visible to the storage provider.

The existing recovery key is stored separately in private configuration. Where the owner enables independent GitHub scheduling, the recovery key and provider credentials are stored in that repository's encrypted Actions secrets. Authorized backup processes necessarily access the decrypted records and key while exporting and verifying recovery. They do not print records or credentials in normal logs.

Google permissions and use

The runner uses Google's drive.file permission for its backup folder and files. The OAuth refresh credential allows scheduled access without an open browser. It is stored in private device configuration or owner-approved GitHub Actions secrets. Google data is used to store, find and verify the owner's backups; it is not used for advertising or AI model training, and is not intentionally shared publicly.

Owner control

The owner can revoke Jinam's authorization through the Google Account connections settings, disable a device schedule, or disable the GitHub workflow. Revocation does not delete existing archives. The runner does not automatically delete dated backups. The owner controls archive deletion and must keep a protected recovery-key copy for future access.
