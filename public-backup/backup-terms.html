Backup operation and limits

Jinam Independent Backups is an owner-operated recovery tool for the owner's business records. Configure it only on authorized devices and accounts.

When jobs can run

A computer backup requires that computer to be awake, signed in, online, and able to authorize the database export. An independently configured cloud job does not require the personal computers, Jinam or Codex to be open. Provider outages, revoked credentials, schedule delays and storage limits can prevent a run.

Verification and recovery

A completed local export must pass encryption, checksum and isolated restore checks. A Drive copy is verified only after its identity, private permissions, size and downloaded encrypted bytes match. A displayed past verification date is not a current availability check.

A backup is a dated snapshot. Changes after that snapshot and unsaved work may be absent. Keep the recovery key protected and separate: losing every key copy makes encrypted archives unreadable. Test recovery before relying on an archive.

Storage and live access

The owner must monitor available storage and preserve useful historical copies. No paid storage purchase is authorized by installing this runner. Cloud quotas still apply. Backups do not add capacity to the live D1 database, and Google Drive archives do not automatically replace the live database if it is full or unavailable.

Signing in on another device provides access to the shared live application; an automatic independent copy requires one-time setup on that device.
